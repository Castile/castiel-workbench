# 本机 Claude 与 Codex 接入

2026-10-25，桌面开发版 0.2.0。目标是启动时复用已安装工具的配置与认证，发送消息后才启动模型推理。浏览器预览仍为演示。

## 启动与配置

主进程查找 PATH、macOS 常用安装目录及应用内的 Codex CLI。Finder 启动时读取登录 Shell 环境，超时则回退至继承环境和常见目录；完整环境只在进程内存中使用。登录 Shell 会正常执行用户已有的初始化文件。

Codex 通过 `app-server --listen stdio://` 建立私有管道，初始化后读取有效配置、登录状态与模型目录。Claude 读取用户配置目录下的 settings.json、环境中的模型配置，以及 CLI 的认证状态。原工具继续处理工作空间配置、权限、Hooks 和 MCP；探测摘要不是对全部配置层的完整解析，工作空间覆盖可能使实际模型与首页默认摘要不同，执行时记录工具报告的实际模型。

界面只接收版本、入口路径、配置来源、模型标识、认证是否存在与通用服务名称。不会返回或复制密钥、认证文件、完整环境、原始配置、账号邮箱或自定义服务地址。自动探测补充缺失的已安装工具，保留已停用工具、独立默认设置与可用空间范围。安装或登录变化后可点击「重新检测」。

未安装、未登录、检测失败和连接断开分别显示状态。配置加载不等于账号有额度或模型访问权限；启动探测不提交用户聊天，也不会自动重发旧会话。

## 真实会话

- Codex 使用 thread/start、thread/resume、turn/start，消费真实流式消息与完成事件，停止使用 turn/interrupt。常见命令/文件授权显示单次允许或拒绝，补充问题显示输入表单；未支持的授权请求返回错误，不能自行扩大权限。
- Claude 使用现有 CLI 的 print / stream-json 模式，输入通过 stdin 传入，不做 Shell 拼接；流式与最终消息按消息 ID 合并。保留原工具认证、服务和权限规则，不使用跳过权限参数。此版尚无 Claude 交互权限宿主，原规则未允许的工具操作会标为阻塞。
- 主进程从已保存的会话读取 Agent、模型与空间，拒绝归档、停用和无效模型。发送前先保存用户输入；未绑定目录的空间使用应用数据目录下自己的工作目录，已绑定空间必须存在，不能默认进入主目录或本仓库。
- 保存真实后端会话 ID、工作目录、实际模型、文本、状态与有限工具记录。同工具同目录才续接后端会话。跨工具切换携带工作台中最近的文本记录重新创建目标会话，不混用两种工具的 ID，也不迁移隐藏推理或全部工具状态。
- Codex 后端明确报告旧会话文件不存在时，使用工作台记录重新建立上下文并显示说明；认证、额度与其他服务错误不会伪装成恢复成功。
- 并行上限沿用设置；达到上限明确提示等待，此版不实现持久调度队列。全局禁止执行或会话仅规划时传递工具的只读/规划选项。方法论与会话补充要求传给工具，但这不等于行为回归已通过。

输出持续期间触发有最大等待时间的本地保存。停止优先请求工具中断，Claude 的进程超时后只终止本轮进程组。发送前取消可阻止延迟启动；旧事件不能覆盖新轮次或工具交接。运行时不允许恢复备份；关闭窗口先停止执行并保存。强退后保留最近写入内容并标记中断，不承诺后台续跑或休眠恢复。

## 模块与权限边界

`desktop/discovery.mjs` 负责安装与安全摘要，`rpc.mjs` 处理私有 JSONL 管道，`agents.mjs` 管理适配器和生命周期。preload 只暴露具名 Agent 方法；Renderer 保持 contextIsolation、sandbox 与禁止外部请求的 CSP，不获得任意 Shell、文件系统或原始 IPC 能力。模型网络请求由原 CLI 按现有配置发起。

工具的用户配置、Hooks 和 MCP 继续具有原工具权限；工作台不是这些工具的额外系统沙箱。诊断会按已知凭据值脱敏，但正常模型回复属于用户内容，可能包含用户主动输入的信息。本地工作文档为明文，凭据仍应留在原工具管理。

## 验证与限制

本次 macOS arm64 验证使用已安装的 Claude Code 2.1.252 与 Codex CLI 0.163.0-alpha.10.2：

1. 离线夹具覆盖配置摘要、命令输入、流式去重、错误/权限阻塞、停止、并发限制、只规划、会话续接、旧记录恢复和跨工具 ID 隔离；这些不是供应商可用性测试。
2. 真实 Codex 返回连接验证回复。桌面新建会话后正常退出、重新启动并在同一个后端会话继续发送，成功回答上一轮约定的代号；本地保存恢复与后端上下文续接均有实际证据。
3. 本机 Claude 自定义服务真实返回 `402 Insufficient Balance`。已加载配置并呈现失败，未验证成功推理，未改动用户认证与服务配置。

尚未实现完整文件产物汇总、自动代码验收、所有 Codex 工具请求类型、Claude 交互授权、持久任务调度、自动发布及生产更新。会话「本轮完成」只表示工具本轮结束，不等于任务验收、测试通过或部署完成。`CASTIEL_ACCESSIBILITY=1` 仅供原生界面验证启用 Electron 辅助功能支持，正式启动默认不强制开启。

协议会随本机工具版本变化；不兼容时显示检测/运行错误，保留原会话。依据官方 [Codex app-server](https://developers.openai.com/codex/app-server/)、[Claude 无头模式](https://code.claude.com/docs/en/headless)、[CLI 参考](https://code.claude.com/docs/en/cli-reference)及[设置说明](https://code.claude.com/docs/en/settings)实现，并核对本机命令帮助与生成的协议 schema。
