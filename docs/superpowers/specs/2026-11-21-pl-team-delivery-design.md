# PL 工作台 · 团队成长与项目交付

需求设计草案，供本轮评审。当前发布版为 0.4.1。本稿描述下一阶段的交互与验收标准。

## 入口和日常路径

沿用「今日」和「团队」。团队首页以成员名册为默认视图，旁边提供「负载」与「项目交付」。把项目放在团队内，可直接从分工返回成员档案，也符合现有一级导航约定。Agent 工作空间继续由本地目录独立定义。

| 入口 | PL 打开后能做什么 |
| --- | --- |
| 今日 | 查看今日到期的沟通约定和项目任务，快速记事，准备自己的半年度或年度自评 |
| 团队 → 成员 | 按姓名、角色、技能找人，进入成员档案，查看目标、时间线、下次约定和承担的工作 |
| 团队 → 负载 | 按周看人，按任务查看工时来源，预览改派后的双方负载 |
| 团队 → 项目交付 | 按项目查看需求、问题单、任务及人员排期，定位到公司系统的原始记录 |
| 设置 → 系统接入 | 配置数据源和字段映射，预览导入结果，查看上次成功时间与错误 |

例如某成员在发布前发现兼容性问题并推动修复。PL 从成员档案点「记事迹」，写下事实、本人贡献、影响及问题单链接。当天可由这条红事件生成激励信或海报。中期审视时可引用同一条记录。PL 写自己的自评时，可以引用该交付并另写自己在协调中的实际贡献。

## 成员、激励和关键事件

成员沿用已有稳定 ID、角色、技能、容量和项目参与关系。补充本地头像、职责、在岗状态，支持新增、编辑、归档。归档成员仍可按姓名回查历史，未完成工作可批量预览后转交。头像选择本机图片，裁切并压缩为小尺寸缩略图，设置导入体积上限；头像缺失时使用姓名占位。

「记事迹」先填成员、日期和事实，可继续填写角色分工、结果、佐证链接，关联目标和工作项。红事件保存值得推广的实践，可同时记录多名参与者及各自贡献；黑事件保存偏差、实际影响、双方说明、改进约定和复核日期。红黑属性属于具体事件。一次问题可沿原记录补充纠正结果和结案时间。

红事件详情提供「写激励」和「生成海报」。写激励可区分给本人的感谢与在团队群表扬的文案。点击生成海报即在本地排版出图，预览只采用公开标题、所选成员显示名、头像及表扬文案，支持修改和导出 PNG。模板内置中文字体回退，长文提示缩短或分页，导出所见即所得。用户自行发送到团队群。黑事件、辅导纪要和原始佐证仅出现在 PL 的档案及授权选用的评审材料中。

## 沟通、辅导与绩效

每次 1:1 都可单独记录议题、成员反馈、PL 观察、双方约定、负责人及下次跟进日期。到期事项在「今日」打开原沟通记录，完成后回填结果，可约下次。日常沟通可发生在绩效周期的任何阶段。

| 周期阶段 | 必须能留下的内容 |
| --- | --- |
| 目标制定 | 周期起止日、目标、衡量标准、预期结果、双方确认情况 |
| 中期审视 | 逐目标的实际进展、引用事迹、障碍、需要的支持，调整目标时保留原约定 |
| 绩效评价 | PL 对每项目标的判断及证据、成员意见、草稿与确认版本 |
| 结果沟通 | 沟通日期、已传达的结果、成员反馈、待解决分歧及后续行动 |

「我的绩效自评」默认选择上半年、下半年或全年，支持调整起止日以适配公司周期。勾选自己的目标、成果和项目材料，用“我的动作、交付结果、对团队的影响、下一步改进”组织草稿。半年材料可在年度复用，同一事迹按记录 ID 去重。团队成员的成果需要单独说明 PL 的贡献。评价和定稿由 PL 决定。

激励事迹、沟通总结和自评共用「AI 润色」交互。原文先落本地草稿，用户选中要润色的段落、可引用的事实，确认这次发给所选 Agent 的内容，再按现有模型配置调用。展示原文和建议版，可编辑、采纳、保留原文或重试。保留来源引用，提示核对新增数字与归因。失败时保留输入。桌面 Agent 的工具访问范围须与发送预览一致，文稿润色采用仅文本调用。

## 项目交付和接入策略

需求可关联多条任务和问题单；问题可关联受影响需求与修复任务。三类条目共用负责人、来源、状态、截止日期和详情链接，按类型提供验收条件、严重程度或投入工时。复用现有任务 ID 及人员周容量，团队负载只汇总排入该周的任务工时，避免父需求与子任务重复计算。

接入分三种方式。本地手工维护可先用完整流程；CSV/JSON 导入适合缺少 API 的系统；可配置的只读 API 适合持续更新。实体、字段、人员标识和状态映射按系统实例保存，导入前预览新增、更新、无法匹配和冲突。以“系统实例＋实体类型＋远端 ID”识别记录，重复导入更新同一项。保留原始状态、链接和最后成功时间，失败保留上次成功结果；人员映射支持手动处理重名。外部负责的字段在源系统编辑，本地排期备注、辅导和绩效材料独立保存。

建议在每条外部任务旁并列显示「源系统负责人」和「本周计划执行人」。例如工单由甲负责，PL 将下周 8 小时排给乙，则工单仍显示甲，乙的下周负载增加 8 小时。再次同步时保留本地安排；后续源系统改派时提示 PL 复核现有排期。未单独指定执行人时使用源系统已映射的负责人；无法匹配的列入待分配。归档成员时只转交本地安排，外部工单提供原系统改派入口。

建议先交付读取和跳回源系统处理的能力。若公司要求从工作台改派、流转和关闭工单，需增加按系统声明可写字段、用户确认变更、写入前版本检查、结果回读及变更记录。首个真实系统的接口、鉴权和允许写入的操作需要与 PL 确认。连接器由桌面主进程执行，通过限定来源的具名接口读取工作项；凭据保存在系统凭据库，导出映射模板只包含非敏感配置。新连接器沿用同一套映射、预览和错误处理。

## 交付顺序和验收

1. **团队日常**：从既有文档升级，原成员与历史任务仍可打开。用虚构成员验证头像、红黑事件、跟进、检索以及重启恢复。红事件导出的 PNG 可直接发群，包含预览选择的字段。
2. **绩效周期**：用同一成员走完四个阶段，跟进能从今日回到对应档案。用上下半年各一条材料生成年度自评。验证模型不可用时草稿可恢复，有效模型返回的润色结果须由用户采纳。
3. **项目交付和公司系统**：本地排期与负载使用同一条任务；导入同一批需求、问题和任务两次无重复；断开公司网络后仍可查看上次成功的数据。用脱敏样例验证映射，首次真实联调单独记录系统、权限和结果。

各阶段覆盖 macOS 和 Windows。备份与恢复涵盖新增资料、记录间关联及头像。升级旧版时缺省新增集合，文档容量及头像存储需在技术设计中验证。正式接入前，系统名称、接口样例、鉴权方式和读写范围为待确认项。
